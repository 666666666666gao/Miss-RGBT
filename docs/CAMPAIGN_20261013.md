# 第一轮配对实验

E0与控制器的启动源码版本见 `reports/SOURCE_VERSION.txt`。随后、正式训练尚未开始时，对齐了focal整batch归一化；正式E3/E4单独固定于 `reports/FORMAL_TRAIN_SOURCE_VERSION.txt`，各训练目录保存该版本及实际源码哈希。启动收据与初始哈希在 `logs/campaign_20261013_v1/`，不能用初始控制器哈希覆盖后续训练修订。

顺序为 E0完整输入全479序列 → E3与E4并行训练 → 各自完整和Miss的全479序列。控制器使用 nohup 和子进程退出码，本机 PATH 没有 screen；不安装额外工具，不静默重试。任何阶段失败保留原始日志，不继续其依赖阶段。

E3=共享双路任务监督+正向任务响应KD；E4=E3+第6块后的局部补偿。两者固定 seed2027，从同一epoch20重新初始化优化器，train882训练。暂不启用反向反馈，不把 smoke 权重拿来正式训练。

每个模型5轮、每轮20000样本、microbatch4、累积2、有效batch8，12500次优化器更新。两路每次各处理2模板与3搜索。头部/补偿LR1e-4，backbone LR1e-5，AdamW、weight decay1e-4、gradient clip0.1；仅原生box_head的BatchNorm冻结，保持baseline设置。固定末轮权重进行本轮比较，不能看测试分数再挑轮次。

实测25次更新：E3/E4约55.74/56.31秒；扣除首步启动后约1.96秒/更新，预计正式训练各6.8小时，运行和存盘可能增加。峰值17.29/17.48GB，均低于单卡24GB。速度检查只核验了首个update最后一个search microbatch哈希相同，未据此声称全部模板、mask或训练样本已逐项验证；正式入口记录首个update各search microbatch哈希。

完整输入E0预计约60～90分钟；正式训练约7小时；两个模型全部四组评估再约3～5小时。合计约11～14小时。按实际运行速度更新估计。

首次远程进度节点设在E0启动后约75分钟，临近完成才读取结果；若未完成，按240秒间隔查询。训练首次必要诊断设在正式启动后约90分钟，检查有限损失、真实更新和首轮保存；最终节点设在约6.5小时。没有必要时不反复轮询。

主目标仍未达成；第一轮只隔离补偿相对同训练量E3的作用。E1/E2、反向反馈、匹配参数投影和最终多种子尚未完成，不能把本轮作为三个贡献的充分证据。
