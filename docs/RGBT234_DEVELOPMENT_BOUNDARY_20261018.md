# RGBT234 参数开发边界

2026-10-18 对服务器 `/data2/wangwj/dataset/RGBT234/RGB_T234` 做了只读清点：目录下有234个序列目录，根目录有 `rgbt234.txt`，每个序列包含 visible/infrared 图像和对应 `visible.txt`、`infrared.txt`、`init.txt`。没有发现独立的 train、val 或 development 目录，也没有发现第二套 RGBT234 序列名单。

因此，本项目当前没有经过认证的 RGBT234 开发集。已经得到的 RGBT234 完整/Miss指标必须视为正式测试结果，不能用来挑选修复宽度、层数、K、模板门限或训练轮次后再把同一组分数写成无偏测试结果。

后续有三种合法路径：

1. 用外部开发数据或作者明确提供的开发划分先选配置，再在234序列上做一次固定评估；
2. 预先声明一个序列级 RGBT234 开发/保留划分，开发分数只作内部诊断，保留集结果单独报告，不能称为完整官方测试分数；
3. 在没有新开发数据前，冻结当前统一配置，把 RGBT234 只用于一次正式比较，不进行测试集驱动的内部参数选择。

当前采用第3条。E3/E4-allBN和U0/U1/U2结果均没有用RGBT234分数选参。LasHeR 的 train882/val97仍是项目已有开发边界，但原始E0历史是否暴露val97尚未认证；它不能自动成为RGBT234的开发集替代品。

这项边界意味着：当前 RGBT234-Miss 未达到88.1/64.3的结果是真实诊断证据，但不能通过在234个测试序列上继续搜索内部参数来追目标。若要推进数据集专用配置，必须先补充外部或预先封存的开发协议，并让同一数据集的完整/Miss共用选定配置与权重。
