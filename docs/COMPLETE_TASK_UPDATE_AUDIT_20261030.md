# 完整任务的实际更新诊断

2026-10-30，服务器28，独立CPU诊断。目标是检查当前共享模型中，增加缺失任务和正向KD后，实际AdamW更新对完整任务的影响。

## 固定设置

- 历史A utility最终epoch20、50000更新的同一checkpoint；不是正在写入的28号机训练权重。
- 三种分支分别从相同模型和已保存AdamW状态开始：仅完整任务、完整+缺失任务、完整+缺失任务+原配置正向KD。
- 每种分支只执行一次有效batch8更新，microbatch4、累积2；全BN运行统计冻结。
- 两份相同真实训练microbatch用于更新，另两份真实训练microbatch用于额外损失观察；后者属于train882，不是val或Test。
- 每份microbatch固定完整前向的随机种子，真实可用标识和patch mask固定，记录图像、标注及mask哈希。
- 缺失前向不读取完整前向的激活值。正向KD目标停梯度，与原生损失一致。
- 不加入utility辅助监督，本次不检验该项；不将一次更新称作完整A训练的替代。
- 使用保存状态中的实际学习率和AdamW动量；clip_grad_norm沿用配置。记录原始方向与更新后的参数步长，避免把原始梯度方向当成最终参数步长。

训练样本上的损失复测保持训练模式并重放相同随机种子；另外8个训练样本的损失用eval模式复测。两种口径分别比较自己的更新前后值，不把它们混成同一个指标。

## 证据与解释规则

报告保存每个分支的：

- 完整任务梯度与该分支原始梯度的内积。
- 完整任务梯度与实际AdamW参数变化的内积。
- 完整任务在更新样本和另外8个训练样本上的损失变化。
- 梯度裁剪前范数、实际学习率、输入哈希、checkpoint哈希及源码哈希。

原始梯度内积为正，仅表示普通负梯度方向下的一阶局部一致性；它不能取代有动量、预条件和裁剪的真实更新观察。实际参数步长的一阶预测同样不能保证未见序列或闭环跟踪指标。

单次配对更新只诊断这一检查点、这些样本和该优化器状态。尤其不能从很小的额外样本损失变化认定普遍退化、统计显著性或梯度冲突是最终基准差距的原因。若没有负方向或稳定伤害证据，不为凑第三模块强行加入梯度投影。

两组额外任务相对完整任务的原始方向差值仍为正：增加缺失任务对应约+71.670993，进一步增加加权KD对应约+0.729184。当前样本不支持“原始负梯度冲突是主要原因”的判断。虽然三种更新都降低更新样本的完整损失，后两者的实际改善幅度明显小于仅完整任务；这发生在没有该原始负向冲突的情况下。

额外8个训练样本的损失变化量仅约1e-5量级，没有重复样本集或不确定性估计，不能称为显著退化。也不能把训练样本上的改善减半直接换算为基准PR/SR下降。
